# 视频号文案提取器

把微信视频号的视频，变成可以复制、可以改写的**文字文案**。

全流程在本机完成：视频在一台电脑上下载和解密，语音识别在你自己的显卡上跑。
音频和视频**不会**上传到任何第三方服务器。

---

## 快速开始

双击 **`启动.bat`**。

- 首次运行会自动安装环境（下载约 2.5 GB 的 CUDA 版 PyTorch，装完 `.venv` 约 5.4 GB），
  脚本会自动从上海交大 / 官方 / 阿里云镜像里挑最快的那个下载，请保持网络畅通。
- 装好后会自动打开浏览器界面：<http://127.0.0.1:8765/>
- 以后每次双击 `启动.bat` 即可直接使用。

> **磁盘占用**：`.venv` 约 5.4 GB，`models/`（识别模型）约 2 GB，
> `wheels/` 约 2.4 GB。`wheels/` 只是安装缓存，**装好后可以整个删掉**，
> 需要重装时脚本会重新下载。

## 三种输入方式

| 方式 | 适用场景 | 需要什么 |
|------|----------|----------|
| **录制电脑声音** ⭐ | 视频在微信里能播、但拿不到文件 | **什么都不用**，播一遍就行 |
| **本地视频 / 音频** | 手上已经有文件 | 无需任何配置 |
| **视频号分享链接** | 直接粘贴链接，全自动 | 腾讯元宝登录态（见下） |
| **视频直链 + decode_key** | 从其它下载工具拿到了直链 | 直链，加密视频需附 decode_key |

### ⭐ 录制电脑声音（推荐，免登录）

视频号视频在微信里能正常播放，但文件拿不到 —— 那就把**电脑正在播放的声音**录下来做识别。
声音在电脑内部是数字信号，环回录制等于无损拿到音轨，识别效果和直接读文件一样。

1. 在微信里打开这条视频号视频，**让它播起来**（保证有声音）；
2. 切到本工具，选「录制电脑声音」标签，确认设备是**★默认输出**那个；
3. 点「开始录制」，回去把视频播完（或者重播一遍）；
4. 点「停止并转写」，稍等就出文案。

实测：52 秒的视频，录制 + 识别约 75 秒，识别出 209 字，关键内容全部命中。

> 用的是 Windows 的 WASAPI 环回（`pyaudiowpatch`），录的是系统内部声音，
> 不走麦克风、不依赖环境安静。

### 怎么拿视频号分享链接

微信里打开那条视频 → 右下角 **「分享」** → **「复制链接」**，得到形如
`https://weixin.qq.com/sph/xxxxxxxxxx` 的地址，粘贴到界面里。


### 登录态会被保存（只需扫码一次）

「一键获取登录态」或手动导入成功后，登录态会写入项目内的 `config.json`，
下次启动自动复用，不用重复扫码。该文件在 Windows 上用 `icacls` 收紧为**仅当前用户可读写**。

另外：如果某条分享链接因为未登录而失败，**登录成功后界面会自动重试刚才那条链接**，
不用再手动粘贴一遍。

### 关于「解析通道」（重要）

工具解析分享链接时走两条通道，界面日志里能清楚看到走到了哪一步：

| 通道 | 是否需要登录 | 能拿到什么 |
|------|--------------|------------|
| **1. 公开预览接口** | 不需要 | 视频标题、作者、封面、点赞评论数、`dynamicExportId` |
| **2. 元宝换取 generalToken** | 需要 | 视频直链 + `decodeKey`（**提取文案必须走这条**） |

原因：微信的 `get_feed_info` 接口，用 `exportId` 取视频时必须带一个 `generalToken` 凭证。
**token 为空时，微信一律返回** `{"errMsg":{"type":2,"title":"此内容暂时无法播放"}}`
—— 看起来像"视频被删了"，其实只是凭证没带上。

这个 token 只有两个来源：微信客户端（通过 WeixinJSBridge 注入页面）或腾讯元宝。
桌面浏览器打开分享链接只能看到封面 + 二维码，因此**必须登录一次元宝**才能取到视频。

### 怎么获取腾讯元宝登录态（只需配置一次）

解析分享链接要借用腾讯元宝的接口，所以需要一个登录态。界面里提供了两种方式：

#### 方式一：一键获取（推荐，不用碰开发者工具）

1. 在界面里展开「登录态设置」，点 **一键获取登录态**；
2. 程序会弹出一个小浏览器窗口（用的是系统自带 Edge/Chrome 的**独立配置目录**，
   不影响你日常浏览器的任何数据）；
3. 在窗口里用**微信扫码登录腾讯元宝**；
4. 程序检测到登录成功后自动读取登录态、关闭窗口并保存。

#### 方式二：手动粘贴

程序支持直接粘贴 Cookie 串，也支持整段「复制为 cURL」、请求头片段、Cookie 插件导出的 JSON。

**最省事的做法（复制为 cURL）**：

1. 浏览器打开 <https://yuanbao.tencent.com> 并扫码登录；
2. 按 **F12** → 切到 **网络 / Network** 面板；
3. 在筛选框里输入 `yuanbao`，只留下元宝自己的请求；
4. 在任意一条请求上 **右键 → 复制 → 以 cURL 格式复制**；
5. 把整段内容粘到界面的输入框里，点 **导入并保存**。

> ⚠️ 注意别选错请求。像 `api.aida.qq.com`、`google-analytics`、`sentry`、`v2_upload`
> 这些都是第三方统计上报，**不含**元宝的 Cookie，选了也提取不到。

**为什么推荐 cURL 而不是手动复制 Cookie 那一行**：登录凭证通常在 HttpOnly Cookie 里，
「以 cURL 格式复制」拿到的是完整请求头，一个都不会漏。

Cookie 只在你本机和腾讯元宝之间使用，不经过任何第三方服务器。失效后重新获取一次即可。

## 识别引擎怎么选

| 引擎 | 特点 | 建议 |
|------|------|------|
| **Paraformer 中文** | 阿里 FunASR 中文模型，自带标点和句级时间轴 | **默认**，中文口播效果最好 |
| **SenseVoice** | 速度最快（显卡上远快于实时） | 视频量大、追求速度 |
| **Whisper large-v3** | 多语种，中英夹杂更稳 | 视频里有大段英文时 |

首次使用某个引擎时会自动从 ModelScope 下载模型（约 1 GB），缓存在
项目内的 `models/` 目录，之后离线可用。

## 输出文件

每次任务会新建一个目录 `output/task_<时间戳>/`，里面包含：

| 文件 | 说明 |
|------|------|
| `<标题>.txt` | 纯文案，已按语义分段 |
| `<标题>.srt` | 带时间轴的字幕，可直接导入剪辑软件 |
| `<标题>.md` | 带元信息的文稿（作者、时长、字数、分段） |
| `<标题>.json` | 完整结构化数据（分段、逐句时间轴、原始接口响应） |
| `<标题>_decrypted.mp4` | 解密后的无水印视频 |

## 技术原理

这个工具没有用任何第三方解析网站，核心链路都是自己实现的：

**1. 解析分享链接**

参考开源项目 `ltaoo/wx_channels_download` 的实现：

```
POST https://yuanbao.tencent.com/api/weixin/get_parse_result
     {"type":"video_channel_url","url":"<分享链接>","scene":1}
  -> data.wx_export_id、data.playable_url（含 token 与 eid）

POST https://channels.weixin.qq.com/finder-preview/api/feed/get_feed_info
     {"baseReq":{"generalToken":token},"exportId":eid}
  -> 视频元信息 + media[].url + media[].decodeKey
```

**2. 解密视频**（`app/isaac64.py`）

视频号 CDN 上的文件**前 128 KB** 被加密，算法是：

- 用接口返回的 `decode_key` 作为种子初始化 **ISAAC64** 伪随机数生成器；
- 生成 131072 字节密钥流；
- 与文件前 131072 字节做 XOR，其余部分是明文。

本项目是 Go 参考实现的逐行等价 Python 移植（uint64 全部显式掩码）。
解密正确性已用真实加密样本验证：解密后偏移 4 处出现 MP4 的 `ftyp` 签名。

**3. 语音识别**

（拿不到文件时）先用 `pyaudiowpatch` 做 WASAPI 环回录制，把系统正在播放的声音存成
48kHz 立体声 WAV，再交给下面这条链路。


PyAV 解码出 16 kHz 单声道 PCM → FunASR（Paraformer / SenseVoice）或
faster-whisper 在本地 GPU 上推理 → 标点与句级时间轴 → 按停顿与长度自动分段。

## 实测记录：真实视频号视频全流程提取成功

目标：`https://weixin.qq.com/sph/ARBFNO8PaW`（《凤命轮回：弃婴渡世-第14集》@ 果粒AI漫剧）

```
通道1 公开预览  -> 确认链接有效：《凤命轮回：弃婴渡世-第14集》/ 果粒AI漫剧
通道2 元宝      -> generalToken 已获取（来自 playable_url，92 字符）
                -> 命中 exportId(eid)
下载 5.2 MB -> 明文 MP4（无需解密）-> 音轨 51.0 秒 -> 识别 208 字
总耗时 21.7 秒
```

**过程中的两个关键坑（已修复并有回归测试）：**

1. **`token` 取错字段**：元宝返回里 `cover_url` 和 `playable_url` 都带一个叫 `token` 的参数。
   前者是封面图的 CDN 凭证，后者才是 `generalToken`。取错会得到
   `{"errMsg":{"type":2,"title":"此内容暂时无法播放"}}` —— 一个**极具误导性**的错误。
   修复：`_hunt(..., prefer=("playable",))` 强制优先 `playable_url`。
2. **新版响应没有 `media` 数组**：加密那套结构是 `feedInfo.media[].url` + `decodeKey`；
   实际接口现在返回的是 `feedInfo.videoUrl` / `h264VideoInfo.videoUrl`，
   **而且没有 `decodeKey`** —— 实测这类视频是明文 MP4（`ftyp` 就在偏移 4），压根不用解密。

## 三个提效功能

### 1. 批量处理

「视频号分享链接」那一栏现在是**多行输入框**，一行一条链接，点一次就能排队处理。

- 也可以把微信里复制的**整段文字**直接粘进来 —— 会自动挑出里面的链接、自动去重
- 输入框下面实时显示「识别到 N 条链接」
- 任务**串行排队**执行（共用一份识别模型，避免显存争抢）
- 每条独立显示进度和结果，单条失败不影响其它
- 每条结果都有自己的「复制文案 / 打开文件夹 / 下载 TXT」

### 2. 复制文案

单条提取完成后，结果卡片上有 **「复制全文」**；
批量模式下**每条结果都有自己的「复制文案」**；
历史任务里每条也有「复制」按钮，进详情页还有「复制文案」。

### 3. 历史任务

界面新增「历史任务」标签页，所有提取过的文案都在这里：

- 每次成功提取**自动记录**（标题、作者、字数、引擎、时间、正文）
- 点「查看文案」直接看全文，可一键复制
- 文案正文**另外存了一份**，就算输出目录被清掉，历史里依然看得到
- 「导入已有任务」可以把 `output/` 里以前提取过的任务补进来
- 删除只删记录，**不动磁盘上的文件**

记录保存在项目根目录的 `history.json`，最多保留 500 条。

### 按「短剧 / 集数」分文件夹归档

输出目录会自动分层，同一部剧的剧集收在一起：

```
output/
├── 凤命轮回：弃婴渡世/          ← 短剧名（从标题里识别）
│   ├── 第14集/
│   │   ├── 凤命轮回：弃婴渡世-第14集.txt / .srt / .md / .json / .mp4
│   ├── 第15集/
│   └── 第16集/
└── 雪夜藏金龙，善妇福满门/
    └── 第1集/
```

命名规则：

| 情况 | 上级文件夹 | 任务文件夹 |
|------|-----------|-----------|
| 标题里有「第N集 / 第N话 / EP12」 | **短剧名**（去掉集数后的部分） | `第N集` |
| 标题里没有集数 | **账号名** | 标题 |
| 两者都没有 | 不分组，直接放 `output/` | 标题或时间戳 |

标题里的 `【】`、首尾分隔符、非法字符都会自动清理（`/ \ : * ? " < > |` 换成 `_`）。
同名目录会自动加序号，不会覆盖。

**已经有历史文件的话**：历史任务页点「整理文件夹」，会把以前散落的
`task_*` 目录按新规则重新归档（只动本程序建的任务目录，其它文件一律不碰）。

历史任务页也按短剧分组显示，一眼能看到某部剧已经提取了哪几集。

### 把每集的 txt / mp4 汇总到一起

提取完整部剧后，33 集的 txt 散在 33 个文件夹里，想一次性拿去用很不方便。
双击 **`整理剧集文件.bat`** 就能把它们各归一堆：

```
凤命轮回：弃婴渡世/                       整理后 ↓
├── 第14集/凤命轮回：弃婴渡世-第14集.txt  ┐
├── 第15集/凤命轮回：弃婴渡世-第15集.txt  ├─► 凤命轮回：弃婴渡世-文案TXT/   （全部 txt）
├── 第16集/凤命轮回：弃婴渡世-第16集.txt  ┘
├── 第14集/凤命轮回：弃婴渡世-第14集.mp4  ┐
├── 第15集/凤命轮回：弃婴渡世-第15集.mp4  ├─► 凤命轮回：弃婴渡世-视频MP4/  （全部 mp4）
└── 第16集/凤命轮回：弃婴渡世-第16集.mp4  ┘
```

汇总文件夹名带短剧名，单独拷走也认得出是哪部剧。用法：

| 操作 | 效果 |
|------|------|
| 双击 `整理剧集文件.bat` | 列出 `output/` 里的所有短剧，输入序号即可 |
| 把短剧文件夹**拖到 .bat 上** | 直接整理那一部 |
| `--move` | 剪切而不是复制（默认复制，原文件夹不动） |
| `--merge` | 额外生成一个按集数排好序的全集合集 txt |
| `--dry-run` | 只预演，不动任何文件 |

几个细节：集数按**数字**排序（第2集 在第10集 前面）；重复运行安全，已整理过的会自动跳过，
不会堆重复文件；完成后会报告哪几集缺 txt / 缺 mp4。只依赖 Python 标准库。

## 减少错别字：文案校对

语音识别是**逐音判断**的，遇到同音字只能靠上下文才改得对。典型例子（真实出现过的）：

| 识别结果 | 正确写法 |
|----------|----------|
| 就算这里了，点个恨通 | 看到这里了，点个赞吧 |
| 这小的山窝留不接 | 这小小的山窝留不住 |
| 一花去梅韵 | 一花去霉运 |
| 老愿皆承 | 所愿皆成 |
| 青瘦身影莫入 | 清瘦身影没入 |
| 传送他的善举 | 传颂他的善举 |

工具提供两道校对工序，**互为补充**：

### 1. 固定替换表（离线，默认开启）

内置 18 条短剧常见套话与同音字修正，**不需要任何 Key**，每次提取自动生效。
在「文案校对设置 → 自定义替换表」里可以自己加，每行一条，格式：

```
错词=对词
就算这里了，点个恨通=看到这里了，点个赞吧
```

### 2. AI 上下文校对（推荐，需要一个 API Key）

把整段文案交给大模型，让它**根据上下文**改掉识别错的同音字：

- 兼容任何 OpenAI 格式的接口，默认 DeepSeek（`https://api.deepseek.com` + `deepseek-chat`）
- Key 只存在本机 `config.json`，只发给你自己填的那个接口
- 提示词严格限定「只改错别字，不改写、不增删」，并会校验返回长度，模型抽风时自动忽略结果
- 没填 Key 就自动跳过，只跑固定替换表

设置入口在主界面下方的「文案校对设置」。里面还有**「试一下」**，
粘一句识别错的文案进去，就能立刻看到两道工序各自的效果。

> 顺带修了个坑：`faster-whisper` 与 `huggingface_hub` 1.x 不兼容
> （报 `metadata_errors`），已把 hub 钉在 0.x，安装脚本里也写死了。

## 常见问题

**Q：提示「需要腾讯元宝登录态」？**
按上面步骤配置 Cookie，并点「检测登录态」。

**Q：提示 401？**
Cookie 过期了，重新登录元宝再复制一次。

**Q：识别很慢？**
确认界面顶部显示的是 GPU 型号而不是「未检测到 CUDA」。
若显示 CPU，说明 PyTorch 装成了 CPU 版，重跑一次 `setup_env.ps1`。

**Q：视频没有声音 / 提示没有音轨？**
纯音乐或无人声的视频提取不出文案，这是正常的。

**Q：能不能批量？**
命令行支持：`.venv\Scripts\python.exe -m app.cli --help`，
可写脚本循环调用。
