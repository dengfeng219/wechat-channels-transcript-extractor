# 视频号取视频的真实架构（逆向结论）

---

## 附：视频号取视频的真实架构（逆向结论）

为了搞清楚"到底能不能不登录拿到视频"，我把三条链路都验证了一遍：

**1. 纯 HTTP（桌面浏览器 / 本工具）**

```
POST /finder-preview/api/feed/get_feed_info
  {baseReq:{generalToken:""}, shortUri:"<sph 短号>"}
-> 标题 / 作者 / 封面 / 点赞数 / sceneInfo.dynamicExportId   ← 无需登录

  {baseReq:{generalToken:""}, exportId:"..."}
-> {"errMsg":{"type":2,"title":"此内容暂时无法播放"}}        ← 永远这样
```

即：**HTTP 通道能拿到元信息，但拿不到视频**。视频必须带 `generalToken`。

**2. 视频号 Web 应用（微信内打开时）**

抓包发现它**根本不发 HTTP 取视频**，而是把一切交给微信原生层：

```js
WeixinJSBridge.invoke("finderH5ExtTransfer", {
  url: "/cgi-bin/micromsg-bin/pc_findergetpcreddot",
  cgi_cmdid: 23911,
  req_json: '{"finder_basereq":{"scene":140,...},"need_object":1}',
  h5AuthToken: ""
})
```

这些 `cgi-bin/micromsg-bin/*` 接口**只存在于微信私有协议里**，
我用 HTTP 直接 POST 得到了 `{"errCode":-1,"errMsg":"Cannot POST /cgi-bin/..."}`。
也就是说：**凭证由微信客户端原生层签发，浏览器里造不出来**。

**3. 腾讯元宝（本工具采用）**

```
POST yuanbao.tencent.com/api/weixin/get_parse_result   ← 需要元宝登录态
  -> data.playable_url 里带 token(generalToken) + eid
再拿 token 调 get_feed_info -> 视频直链 + decodeKey
```

**结论**：视频号视频不存在"完全免登录的 HTTP 获取方式"。
要么登录一次腾讯元宝（推荐），要么走微信客户端的原生层。
本工具选择前者，并且已经把后续的解密 + 语音识别全部本地化。
